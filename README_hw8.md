# Домашка 8 — Анти-галлюцинатор III

Ветка `hw8` поверх `hw5` (PR #3). Основные тесткейсы: basic, 4th-symbol,
employer, intersection; дополнительно personal. Четыре модели из эксперимента
с односторонними автоматами, по 20 независимых запросов на пару модель × тесткейс.

## Запуск

```bash
python -m pip install -r requirements.txt
python -m pytest -q
# OPENAI_API_KEY, DEEPSEEK_API_KEY, QWEN_API_KEY — тот же OpenRouter-ключ,
# как в предыдущем эксперименте; можно задать в .env (не коммитить).
python -m src.regex.runner --runs 20
python -m src.pipeline.evaluator
python -m src.regex.evaluator
python -m src.regex.report
```

На GitHub Actions `run-regex` тесты выполняются перед платными запросами.
Push нового workflow в `hw8` запускает эксперимент с уже настроенным секретом
`OPENROUTER_API_KEY`. Pull request запускает только тесты. Результаты и сырые
ответы сохраняются в artifact `regex-experiment`, даже при частичном сбое.
Прогон не меняет ветку автоматически. Неполная выборка явно помечена в отчёте.

## ANTLR4 и Томпсон

`src/regex/Regex.g4` задаёт приоритеты: звезда, конкатенация, альтернатива.
`root` требует EOF. Ошибки лексера и парсера приводят к отказу, а символы
алфавита дополнительно проверяются по тесткейсу. Пустая регулярка и ε не
разрешены условием; пустое слово может приниматься через звезду.
Сгенерированы lexer, parser, Visitor и Listener; Томпсон реализован посетителем.

Сгенерированные файлы хранятся в репозитории; для их воспроизведения:

```bash
curl -fL https://www.antlr.org/download/antlr-4.13.2-complete.jar -o /tmp/antlr-4.13.2-complete.jar
java -jar /tmp/antlr-4.13.2-complete.jar -Dlanguage=Python3 -visitor -listener \
  -Xexact-output-dir -o src/regex/generated src/regex/Regex.g4
```

Runtime закреплён на версии 4.13.2. Код посетителя создаёт фрагменты с входом
и выходом и соединяет их ε-переходами. Перед использованием существующей
детерминизации ε-переходы устраняются через замыкания (включая пустое слово).
Эквивалентность проверяется минимизацией и канонической нумерацией DFA,
как в ДЗ5. Лимит ресурсов даёт неизвестный вердикт, а не ложное доказательство
неэквивалентности. В отчёте неизвестные результаты видны отдельно.

В `reports/final_table_regex.md` — таблица, сравнение с точными результатами
генерации автоматов и выводы. В `data/raw_regex/` — неизменённые ответы и
JSON с промптом, конфигурацией модели и временем каждого запроса.
Повторный запуск пропускает существующие ответы, включая пустые.
